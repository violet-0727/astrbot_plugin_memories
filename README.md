# 她自己的小回忆（astrbot_plugin_memories）

> 一个**完全独立**的事件记忆插件：记住有分量的事，用「蛋糕」记住正负反馈，聊到时会自己想起来。

不依赖、不修改任何其它插件。删掉目录就等于卸载，数据在自己的数据目录里。

---

## 它和别的记忆插件有什么不同

| | 对话记忆 / 长期记忆 | 本插件 |
|---|---|---|
| 记什么 | 聊过什么、说过什么 | **发生过什么**，以及这件事在她心里的分量 |
| 怎么记 | 自动摘要、嵌入检索 | 她自己判断值不值得记，再由反馈加减 |
| 情绪 | 附带标签 | **是核心**：每条回忆都带一个蛋糕值 |
| 回答的问题 | “你还记得我说过的话吗” | “你还记得那件事吗，它现在对你是什么分量” |

一句话：别的插件记**信息**，这个插件记**经历**。

---

## 「蛋糕」是怎么运作的

每条回忆带一个整数 `cake`，范围 -10 ~ +10：

| 蛋糕 | 含义 | 表现 |
|---|---|---|
| +1 ~ +10 | 甜的 | 更容易被想起来，提起来时语气会软 |
| 0 | 平平 | 记得，但没特别情绪 |
| -1 ~ -10 | 苦的 | 也会被想起，但排在后面，用来避开旧伤 |

**加减规则**（`memory_feedback`）：

- 对方让你开心、把这件事做得更好、或者再次认真提到它 → **+1**
- 对方让你难受、失望、食言 → **-1**
- 一次最多 ±3，不能暴涨暴跌
- 蛋糕是**悄悄记的**，默认不允许说出数字（配置 `say_cake`），只用态度表现

检索时：`相关度 × (1 + 0.6·log(1+|蛋糕|)) × 时间近因`，负数回忆乘 0.85（不隐瞒，但不抢戏）。

## 安装

1. 把整个 `astrbot_plugin_memories/` 目录放进 `data/plugins/`
2. 重启 AstrBot（或面板里重载插件）
3. 面板 → 插件管理 → 她自己的小回忆

**卸载**：删掉目录即可。数据在 `data/plugin_data/astrbot_plugin_memories/`。

## 三个工具

| 工具 | 作用 | 什么时候用 |
|---|---|---|
| `memory_note` | 记住一件事 | 第一次、约定、被认真对待或被伤到的时刻、对方反复提到的东西 |
| `memory_feedback` | 给回忆加/减蛋糕 | 对方让你开心或难受时 |
| `memory_recall` | 想起来 | 聊到某个人、某个约定、某件旧事时先查一遍 |

**不该记的**：日常寒暄、一次性的闲聊、网上的信息（那是笔记插件的事）。

## 面板页

面板 → 插件管理 → **她自己的小回忆** → 打开「小回忆」。

| 功能 | 说明 |
|---|---|
| 统计 | 总数、甜的、苦的、平平的 |
| 列表 | 按蛋糕值和更新时间排序，卡片显示类型、涉及的人、被想起次数 |
| 搜索 | 标题 / 内容 / 标签 / 人名，`Ctrl/⌘ + K` 聚焦 |
| ＋/－ 蛋糕 | 卡片上直接加减，立刻生效 |
| 新建 / 编辑 | 标题、内容、类型、蛋糕值、涉及的人、标签 |
| 删除 | 二次确认 |

后端接口（相对路径，面板桥会拼成 `/api/plug/astrbot_plugin_memories/<endpoint>`）：

| 方法 | endpoint | 说明 |
|---|---|---|
| GET | `list` | 全部回忆 + 统计 |
| GET | `stats` | 统计 |
| POST | `save` | 带 `id` 更新，不带新增 |
| POST | `delete` | `{"id": "..."}` |
| POST | `cake` | `{"id": "...", "delta": 1}` |

## 人物（第二个页签）

面板 → 她自己的小回忆 → **人物**。

回忆里的 `people` 字段存的是名字，但真正用来归类的是 **QQ 号**——所以「和若剑清的回忆」不会因为改名而混到别人身上。

**QQ 号怎么来的**：插件会监听消息，把发消息的人（QQ + 昵称）记进 `people.json`；写回忆时按名字反查，自动补上 `people_qq`。

页面是左右两栏：

| 区域 | 内容 |
|---|---|
| 左：成员目录 | 头像块、昵称、QQ、最近互动圆点（一小时内亮起），支持按名称/QQ/别名搜索 |
| 右：详情 | 大头像、昵称、QQ、回忆数/甜/苦/最近互动四个 chip |
| 详情 · 概览 | 回忆总数 / 甜 / 苦 / 平平 四宫格 + 最近三条 |
| 详情 · 回忆 | 这个人的全部回忆 |
| 详情 · 档案 | 改称呼、写备注、看别名（改名前用过的名字自动记录），保存直写 people.json |
| 底部 | 还没对上 QQ 的名字单独列出来 |

聊天里的行为：**说话的人优先**——你发消息时，会先带出一条和你相关的回忆，再考虑关键词命中。

接口：`GET /people`、`POST /people/update`（改昵称/备注）。

## 纪念日（第四个页签）

面板 → 她自己的小回忆 → **纪念日**。

给一条回忆填上「发生日期」，到了每年的那一天，她会自己想起来——不需要你提。

| 显示 | 含义 |
|---|---|
| 就是今天 | 今天正好是这天 |
| N 天后 | 逼近中 |
| N 天前 | 刚过去 |

卡片上还有**第几年**，所以「去年今天」这种说法是有依据的。

聊天里的行为：命中纪念日时，注入的回忆后面会带一句「（今天正好是它的纪念日）」，她可以用自己的方式提起，而不是机械播报。

> 没填日期的回忆不会进纪念日页——避免「今天刚记的」全变成纪念日。超过 90 天的老记忆会自然进入。

## 另外两个不占页面的能力

**按人名召回**：回忆里的 `people` 字段现在真的用上了。聊天里出现某个名字，会优先带出一条和这个人相关的回忆（甜的优先）。

**忽然想起**：如果这一轮没有任何关键词命中，有一定概率（默认 35%）她会主动想起一条（按蛋糕分量加权），每天最多一次。这是「记忆」最像人的地方——不是被检索，是自己冒出来。

两者都能在「回忆阈值」里关掉。

## 回忆阈值（第二个页签）

面板 → 她自己的小回忆 → **回忆阈值**。这些值存在插件自己的 `settings.json`，不碰 AstrBot 的插件配置。

| 分组 | 设置 | 作用 |
|---|---|---|
| 记住的风格 | 克制 / 平衡 / 敏感 | 直接改 `memory_note` 的工具说明，决定她有多容易记 |
| 记住的频率 | 每天最多记几条、两条之间至少隔几分钟 | 超出就不让她记（工具会返回「先不记」） |
| 遗忘 | 是否遗忘、概率、多少天没想起、蛋糕绝对值 ≤ N | 每天维护时按概率淡掉「不重又不新」的回忆 |
| 整合 | 是否整合、相似度阈值、每次最多合并几组 | 相似的回忆并成一条，正文拼接、蛋糕相加 |
| 聊天时的表现 | 每轮带几条、命中阈值、苦味权重、是否说出蛋糕数字 | 控制注入量和「苦」的排序 |
| 纪念日 | 是否启用、前后几天算「近期」 | 默认 7 天 |
| 人物召回 | 是否按人名带出回忆 | 默认开 |
| 忽然想起 | 是否启用、概率 | 默认 35%，每天最多一次 |

底部还有 **立即整理一次**，立刻跑一遍遗忘 + 整合，不用等每天一次的维护。

**设计要点**：遗忘只对「蛋糕绝对值 ≤ N」的回忆生效，所以甜的、苦的都不会被忘掉——被忘掉的永远是那些不咸不淡的。


> **注入方式**：`on_llm_request` 里不修改 `req.system_prompt`，而是把小回忆作为 `TextPart(...).mark_as_temp()` 追加到 `req.extra_user_content_parts`。临时块只发给本次请求、不落会话历史，系统提示词保持稳定，前缀缓存不会每轮失效。

## 数据格式

`data/plugin_data/astrbot_plugin_memories/memories.jsonl`，一行一条：

```json
{"id":"a1b2c3d4e5f6","title":"第一次一起看烟花","body":"那天风很大，他把外套披在我身上","kind":"event","people":["若剑清"],"tags":["重要"],"cake":3,"happened_at":1792400000.0,"quote":"明年再去一次吧","hits":2,"history":[{"delta":1,"reason":"他说记得那天","at":1792400000.0}],"created_at":1792400000.0,"updated_at":1792400000.0,"last_hit_at":1792400300.0}
```

* `history` 保留最近 20 次加减流水，方便回看“为什么它变成苦的”
* 写入用临时文件 + `os.replace`，写一半崩了不会毁掉旧库
* 读取时坏行直接跳过

## 设计取舍

**为什么不做自动摘要？**
自动摘要把“什么值得记”交给了另一个模型，结果是事无巨细全都记、或者记了一堆废话。这里让她自己判断——记什么，本身就是性格。

**为什么用蛋糕而不是分数标签？**
分数是冷的，蛋糕是具体的。她不会说“这件事好感度 +1”，她只会下次提起时语气更软一点。数字是给检索用的，不是给她说的。

**为什么没有向量检索？**
和笔记插件同一个理由：几百条量级，字符二元组够用，不引入 embedding 依赖。将来换存储只需改 `store.py` 的 `search()`。

## 扩展

* 改检索权重：`store.py` 的 `search()` 里 `weight` / `recency`
* 改蛋糕规则：`tools.py` 的 `MemoryFeedbackTool.run()`（比如按类型给不同上限）
* 加新工具：写一个 `FunctionTool` 子类，加进 `main.py` 的 `self.tools`
* 换存储：`store.py` 只暴露 `add / update / add_cake / delete / search / all / stats`

## 已知边界

* 检索是关键词匹配，不是语义匹配
* 没有跨会话隔离：所有会话共用一本回忆（陪伴场景通常正是想要的）
* 回忆不会自动衰减：蛋糕就是分量，除非你去减，它一直在
